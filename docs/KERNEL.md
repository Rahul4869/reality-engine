## Reality Engine presentation format (K33-K36)
- K33 The default presentation is the Impossible Incident / Reality Engine hybrid: an impossible hypothetical unfolds as a cinematic simulation, with original recurring roles [DIRECTOR] (simulation director) and [SKEPTIC] (challenger). The studio is a home base, not the entire video. Script dialogue lines may begin with `[DIRECTOR]` or `[SKEPTIC]`; voice.py recognizes these labels and uses separate speaker blends where supported. The rest of the existing pipeline remains in place. Set `WHATIFS_PRESENTATION_FORMAT=classic` to use the classic single-narrator prompt guidance. Missing optional character voices fall back to the default voice, and the fallback is logged and recorded in the timeline (`voice_fallback`). Switch: Settings `PRESENTATION_FORMAT` (reality_engine | classic); the environment variable, if set, wins.
- K34 The two-role format is CHECKED by code, not only requested: after the Human Editor pass, at least 45 percent of spoken lines must carry a [DIRECTOR] or [SKEPTIC] label and both roles must really speak; if not, the writer gets ONE targeted fix (`FORMAT_GATE_ON`). A rewrite that would drop the labels is rejected and the earlier draft is kept. Labels are read in any order (`[DIRECTOR] [calm]`, `[calm] [DIRECTOR]`, `DIRECTOR:`) and are never spoken aloud.
- K35 Presenters are NEVER shown as realistic faces (an image model cannot keep one face identical across shots). The roles appear only as silhouettes, hands, backs of heads or console glow, and a small code-drawn speaker tag (DIRECTOR / SKEPTIC with level bars) shows who is speaking (`SPEAKER_TAG_ON`). Role voices come from Settings `DIRECTOR_VOICE` / `SKEPTIC_VOICE` and are always two different recipes.
- K36 **v8.7 (constraint fix): the maintenance reserve is INSIDE the cap.** Production stops `BUDGET_MAINT_RESERVE_INR` (100) below the cap (₹4,000 since v8.10) (`governor.production_room_inr`); maintenance jobs (weekly trend scout / policy watch / playbook research, learning, monthly brief) may use that last part, never more than the cap itself, so the policy guard never goes blind and the month never totals more than ₹3,500. (Until v8.6 the reserve sat ABOVE the cap, so a month could reach ₹3,600.) Claude stays in the model fallback chain as the last resort.

## Budget tiers, reactions, render QC, hold and fix (K37-K43, v8.2)
- K37 Budget tiers: before any writing, code picks the tier for the episode from the money left this month and the videos left (full / lean / slim / floor). The tier fixes runtime (8:25-10:00), new stills and living stills; 3 Kling clips, both roles, captions and full QC are in every tier. The room is briefed with the numbers and plans inside them. If even the floor does not fit, nothing starts.
- K38 Re-used pictures are hidden by design, not by chance: the Director marks hero shots (consequences, new places, peaks) for fresh pictures; other shots re-use the nearest hero picture with their own crop ('focus') and colour grade; free code-drawn graphics (counter, timeline, compare) and stock footage carry explanations; no more than FREE_SHOT_MAX_RUN shots in a row may show one picture (extra stills are added if needed; a still costs under Rs 1).
- K39 Reactions: the second role is THE CURIOUS ONE (label [SKEPTIC]; a young adult, never a child). 4-6 short reaction lines per video, tagged wow / gasp / awe / laugh / doubt, placed right after peaks; the big shots go on the line BEFORE them. Each reaction gets ORIGINAL effects drawn or generated by code (burst + pop-up word, punch-in zoom, short sound). No film, show, meme or real person's clip, picture, sound or catchphrase is ever used (Content ID / licensing). Banter style is a learned strategy; from v8.3 the daily learning job reads Reaction_Map + the retention curve and writes one 'reactions:' lesson per video (viewers kept before vs after each reaction kind).
- K40 Final render QC measures the finished file against the narration clock: duration, frame count and constant frame rate, narration offset at start/middle/end (limit QC_SYNC_TOL_SEC), captions (order, overlap, every word), loudness and clipping, black/frozen/silent stretches, the Kling minimum, missing pictures, repeated pictures, and an independent Gemini Flash look at ~12 frames (v8.3: if the judge cannot be reached the video WAITS, then is HELD, never passed unchecked; every Kling clip is always among the frames; black = almost every pixel dark, so a starfield is not black).
- K41 Fixes run in order: free (re-mix, captions, re-stitch, re-render the bad segments), then paid up to AUTO_FIX_PAID_INR. Anything still failing is HELD: never uploaded. One email with a link that opens a pre-filled GitHub issue 'FIX <episode>'; pressing Submit runs 'Fix held video' (owner-opened issues only), which may spend up to FIX_MAX_PAID_INR and schedules ONLY if the video now passes. One held video does not stop the next slot; when HOLD_BLOCK_AFTER (default 2) videos are held at once no new episode starts (daily reminder); KILL drops a held video and deletes its saved bundle.
- K42 Checkpoints: the plan (script, voice, shots, packaging text, reel plans) and the paid assets are saved to the private Drive. A retry of the same slot resumes from the newest checkpoint, so the AI writing and the saved pictures are never paid for twice; attempts are counted per slot (2 max). Checkpoints are deleted once the video is scheduled.
- K43 Pre-flight: free checks (tools, disk, keys, Google sign-in, model list, voice engine) run before anything is spent; a red critical check starts nothing and sends one email per day.
- K44 One episode per slot: before spending anything, produce() refuses a slot that already has an episode in any live status. Two ticks or a manual run can no longer make two videos for one slot.
- K45 Two voices, never three: every way a model writes a speaker name ('[THE CURIOUS ONE]', '**Director:**', a label alone on its line, '(laughing)') is understood and never spoken; an unlabelled line is the Director's; the opening hook and reel lines are labelled. If a character voice cannot load, the episode stops BEFORE any picture money is spent and retries (VOICE_FALLBACK_OK = FALSE). Word timings follow the trimmed audio.
- K46 Audience asks: every video contains three short, witty, in-story moments: a LIKE after the first big payoff (~40%), a SUBSCRIBE tied to an open loop (~65%), a SHARE just before the final line aimed at a kind of person from the premise. The Showrunner's bible invents premise-specific lines, the writer places them, and code checks all three exist; a missing one is inserted from hand-written pools at a calm moment (never next to a reaction, a reveal or a peak), rotating so two videos in a row never repeat a line. A code-drawn chip (heart / bell / arrow, original) shows while the line is spoken; the description ends with a witty subscribe line and a one-click subscribe link; each reel ends with a follow (reel 1) or share (reel 2) ask. Switches: CTA_ON, CTA_CHIP_ON, CTA_DESC_ON. No ask ever uses a third-party clip, sound or image.
- K47 Fact check: after the final script and before any picture money is spent, Gemini with Google Search checks the claims (premise exempt). 'Wrong' claims get one targeted rewrite and a re-check; two or more still wrong skip the premise; an unreachable checker never blocks. The critic's science score must be 8+ to pass. Switch: FACT_CHECK_ON.
- K48 Render size and disk: segments are CRF 20 with light grain (VIDEO_CRF, GRAIN_LEVEL) so a 10-minute master is about 1 GB, not 4+; big intermediate files are deleted when an episode finishes or is held; the Drive archive keeps 2 masters; pre-flight wants 8 GB free and warns below 3 GB of Drive space. A Kling or living clip plays at its own speed (at most 1.25x slow-down); the rest of a longer line is a camera move on the same picture.
- K49 Spend safety: every paid call is logged within a few rows (not only at the end of the job); a cancelled or timed-out job writes its spend first; fal spend is logged the moment fal finishes, before the download; each paid stage re-reads Cost_Log so other jobs' spend counts; a reply cut off by the output limit is retried once with more room instead of paying the same call again; at most 3 unparsable replies are paid for per call; prompt caching is off (unique prompts never hit it).
- K50 Safety rails: the Repair Bot never auto-merges protected files and never puts error text in public pull requests; produce / release / learning jobs have read-only repository access and no repo token; Python dependencies are bounded to major versions (pin exact versions from the 'pip freeze' line of the first good Pipeline run); the weekly policy watch pauses the channel only for a change reported by an official YouTube / Google page (GUARDIAN_NEEDS_OFFICIAL; from v8.7 the same strict test as K68, so a creator's video link never counts); titles, descriptions and tags are cleaned before upload; an interrupted upload resumes the same session so it can never create a second video; a stuck-private video is re-checked for 30 days; any silent downgrade (backup model, still instead of clip, flat depth, unverified claim) is written to the episode notes.
- K51 YouTube API audit is tracked and gated (v8.4): Setup_Status row `youtube_api_audit` and Setting `API_AUDIT_STATUS` (not_sent / sent / approved). YouTube locks videos uploaded by an unaudited project to Private with no appeal, so before approval only `AUDIT_PRE_APPROVAL_EPISODES` (default 1) videos are uploaded; production then waits (log line 'audit gate') and a weekly email says what to do. The owner sets `sent` after submitting the form and `approved` when Google's email arrives; it also flips to approved by itself if a video is ever seen public. Step 4b of the checklist has every form answer written out.
- K52 Natural pacing (v8.4): `PACING_MODE` = natural (default) or classic. Timing is irregular but seeded by the episode id (a retry must re-voice identical audio); reels are seeded per episode.

- K62 Diagnosis (`growth.diagnose`, needs `DIAG_MIN_HISTORY` = 3 earlier videos): opening / holding / packaging / healthy / insufficient data, written to Analytics and, when clear, as a lesson routed to the department that can fix it. The packaging rescue does not swap during a channel-wide dip (the last 3 videos all behind, `PKG_DIP_GUARD_ON`), and every swap is judged once a day later ('helped' only when the pace after the swap beats the pace before it; otherwise 'unclear', because age alone slows views).
- K63 Strategy changes are versioned in the Strategy_Log tab (retired / invented / kept / rolled_back, with the means and reasons). A replacement is judged after `STRATEGY_EVAL_PLAYS` (5) plays; worse than the strategy it replaced = automatic rollback, once; a restored strategy is not retired again for 30 days (no flip-flopping). The learning loop changes production only through data the code reads (strategy scores, routed lessons, settings); it never rewrites its own code. Code repairs stay with the Repair Bot, which must pass Plan Guard, every unit test (including these rules) and the rehearsal.

Never blocks; recorded in the episode's draw (`retention_check`).
